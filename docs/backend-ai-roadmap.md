# Backend and AI roadmap

**Design target, November 2026.** Anything a developer builds on the backend or AI side with Python or TypeScript and their libraries and frameworks can be built in Corvid. Corvid reaches that through two paths that ship together:

1. **Built into Corvid.** The language and standard library cover what nearly every service and agent needs: typed data, HTTP, persistence, text, cryptography, money, real-time connections, model calls, tools and durable work. Built-in capabilities compose with effects, approval, provenance, replay and budgets.
2. **Typed interoperability.** Any Python package or npm package can be called from Corvid with checked types, on every production target, so the long tail of the Python and TypeScript ecosystems (machine learning, data science, vendor SDKs) is available on day one.

The defining capability stays at the center: a person and an AI agent use the same application through the same typed actions. The organizing principle, from the [platform plan](proposals/corvid-platform-plan.md), is that the application and the AI can always see each other, within what the author declares. Backend and AI grammar is owned here. Browser views and client behavior follow the [browser frontend queue](frontend-roadmap.md#ordered-tasks).

### Task progress

**Native memory safety** (found 2026-11-27, macOS session; brought to the front because it crashes ordinary programs)

- [x] The native cycle collector frees values the program still holds. Any native program that allocates more than `CORVID_GC_TRIGGER` values (default 10 000) can crash with `corvid_release on already-freed allocation` or a segfault: `while i < 20000: total = total + price` on a `Decimal`, a string built in a loop, a list grown in a loop, even a straight chain of eleven string concatenations under `CORVID_GC_TRIGGER=10`. With `CORVID_GC_TRIGGER=0` (collector off) every one is correct, so the refcounting is sound and the collector's marking is not. Reproduced by the ignored test `verifier_audit::a_loop_building_a_string_survives_collection`; the existing fixtures allocate too little for the collector ever to run (the "loop allocating strings" fixture allocates none in its loop). Ruled out so far, on arm64 macOS: the stack-map table exists and its `pc_offset`s are the calls' return addresses; the walk's `sp_at_call = frame + 16` matches the frames checked; declaring loop variables with `declare_var_needs_stack_map` did not fix it. The verifier reports a `String` with refcount 2 where it reaches 1, so one live holder is not a root, most likely an operand held only in a register across a runtime call that allocates (the borrowed-operand peephole for string `+` is a suspect). Stronger: find the missing root, make the fixtures allocate past the threshold under the verifier, and run the native parity suite with `CORVID_GC_TRIGGER=10` so the collector is exercised on every program. Until then a native program that allocates heavily is safer with `CORVID_GC_TRIGGER=0`, which leaks cycles but frees everything else. Fixed 2026-11-27: the cause was the collector running inside `corvid_alloc_typed` after linking the new block but before returning it, with roots taken only from compiled frames' stack maps, so it freed the block being allocated and anything a runtime function was building. `corvid_gc` now finds roots by trial deletion (a block's references from other heap blocks are subtracted from its count; the rest are outside references), which needs no stack walk and sees runtime locals. Every program above is correct at the default threshold and at `CORVID_GC_TRIGGER=10`; `verifier_audit::a_loop_building_a_string_survives_collection` runs un-ignored, and `cycle_collector` tests the threshold collection directly from Rust.
- [x] Exercise the collector across the native suite. Done 2026-11-27: every parity fixture now runs with `CORVID_GC_TRIGGER=1`, through one `native_command` helper, so the collector runs at every allocation. The first such run found a second fault, which is fixed: trial deletion traces every live block, and a block whose fields were not yet written was read as holding references. The allocator now returns traced blocks with empty fields, and the collector stops, naming the type, on any reference to something that is not a live value. With the zeroing removed, many parity tests fail, so the suite now guards it.

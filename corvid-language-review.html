Approval resumption and backend semantics are the highest-priority defects. The benchmark and claim gates currently allow successful results without exercising the property they describe.

Implementation and verification in the working tree

The numbered findings below describe revision baab5465. The working tree includes changes to approval execution, arithmetic lowering, Python target diagnostics, benchmark measurement, contract checks, deployment, the SDK, and the release gates.

  • Each HTTP approval releases one boundary. Concurrent decisions compete for one database transition. The server records a separate execution receipt. A restart can recover a route that tail-calls an agent whose first statement reviews its flat arguments and whose return performs a single supported call. General VM stacks and reconciliation after an external side effect still need implementation.
  • The checked-arithmetic and short-circuit regressions run under Wasmtime. Python integer division, checked overflow and floating remainder were also exercised in generated Python, and a native executable returned the expected negative floating remainder.
  • The generated Linux image passed readiness and returned mock-carrier from the reference connector route. The pagination hook discarded an older in-flight response after reset.
  • The rejection benchmark verified the named guarantee in 34 of 50 cases. The offline provenance probe recovered the expected retrieval sources in 4 of 10 chains. Its fixture identifies one document per retrieval endpoint. The reports describe the remaining mismatches.
  • Startup checks now enforce route execution availability. Broader verification of reachable host tools, jobs, schedules and identity routes remains open.

Original findings and acceptance checks

1. A review decision grants more than one boundary

Source inspection. On approval, the server reruns the whole handler with an always-yes approver. Work before the pause may repeat, and a second approval boundary receives the first decision. Carry an explicit grant tied to the reviewed invocation and effect. Verify a two-boundary route requires two distinct decisions.

2. Approval execution and decision storage can diverge

Source inspection. The pending invocation is cloned under a lock, the handler executes, then the queue records approval. Overlapping decisions or a failed queue write can execute work twice. The queue can persist, while the invocation map is rebuilt empty on restart. Persist a claim and continuation before dispatch, use effect-level idempotency, and test concurrent decisions and recovery after each transition.

3. A resumed handler loses its execution configuration

Source inspection. Startup installs LLM wiring, connector mode and compiled connector operations. The regular request path derives a runtime with a new approver. The approval callback creates a fresh builder and copies only host tools. A resumed connector or configured model can therefore fail after review. Preserve the original configuration and verify the complete approval-to-connector path.

8. Numeric edge cases also disagree between VM and native

Source inspection. Strict integer division in the VM calls wrapping_div even for MIN divided by -1. Native emits signed division. Native float remainder computes a - trunc(a / b) * b.
